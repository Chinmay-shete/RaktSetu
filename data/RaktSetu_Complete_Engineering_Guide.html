🏗️ The 3-Layer Architecture — FAANG Thinking
Each layer is independent, scalable, and replaceable. This is how production systems are designed.
Layer 1Client Layer
What users see and interact with
  • React Web Dashboard — Hospital staff & admin panels
  • Flutter Mobile App — Donor-facing emergency search
  • Authentication: JWT tokens stored securely
  • All communication via REST API only. Never direct DB access.
Layer 2API + Business Logic
The orchestration brain of the system
  • Node.js + Express — All CRUD, routing, middleware
  • JWT Middleware — Every request verified here
  • Cron Scheduler — Batch expiration checks every hour
  • Calls Python AI via internal HTTP with circuit breaker logic
Layer 3AI Engine (Python)
Completely separate microservice for forecasting
  • Flask API — Exposes /predict and /shortage endpoints
  • Prophet Model — Trained on historical transfusion trends
  • Schedule Integration: Reads surgical schedules for accuracy
  • Returns JSON predictions that Node.js acts upon
Storage & Services
External dependencies and data persistence
  • MySQL — Summary counts + granular batch logs
  • Firebase — Real-time push notifications
  • Twilio/WhatsApp — Dispatch alerts, donor comms
  • Google Maps API — Distance matrices, routing
✨ Fault-Tolerance & Idempotency Layer
Ensures system stability even when AI or database failures occur
  • Circuit Breaker: Node.js → Python AI (fail gracefully on timeout)
  • Retry Logic: Exponential backoff for failed requests
  • Idempotency Keys: Prevent duplicate transfers & donations
  • Fallback Behavior: Use cached predictions if AI is down

🗄️ Production Database Schema
7-table normalized design separating aggregates from transactional logs
hospitals
id INT PK AUTO_INCREMENT name VARCHAR(100) address VARCHAR(255) district VARCHAR(50) lat DECIMAL(9,6) lng DECIMAL(9,6) phone VARCHAR(15) created_at TIMESTAMP DEFAULT NOW()
CRITICALblood_stock_summary
Aggregated live counts for fast UI reads
id INT PK hospital_id INT FK → hospitals.id blood_group ENUM('O+','O-','A+',...) total_available INT DEFAULT 0 updated_at TIMESTAMP UNIQUE KEY (hospital_id, blood_group) INDEX hospital_id
CRITICALblood_inventory_batches
Individual items, shelf-life records, expiry dates
id INT PK hospital_id INT FK blood_group ENUM(...) units_in_batch INT status ENUM('available', 'transferred', 'utilized','expired') expiry_date DATE created_at TIMESTAMP INDEX expiry_date INDEX hospital_id
transfer_requests
id INT PK from_hospital INT FK to_hospital INT FK blood_group ENUM(...) units INT status ENUM('pending','accepted', 'declined','completed') trigger_type ENUM('auto','manual') created_at TIMESTAMP INDEX from_hospital INDEX to_hospital
donors
id INT PK name VARCHAR(100) phone VARCHAR(15) UNIQUE blood_group ENUM(...) lat DECIMAL(9,6) lng DECIMAL(9,6) last_donated DATE eligible_on DATE created_at TIMESTAMP INDEX blood_group INDEX eligible_on
surgical_schedules
id INT PK hospital_id INT FK surgery_type VARCHAR(50) count INT scheduled_on DATE created_at TIMESTAMP INDEX hospital_id INDEX scheduled_on
Indexing Strategy: All FK columns, date columns (expiry_date, eligible_on), and hospital_id are indexed. Composite unique key on (hospital_id, blood_group) prevents duplicate summaries.
🛡️ Security Hardening Roadmap
Enterprise-grade authentication, authorization, and protection mechanisms
AUTHENTICATION
🔐 Access Control
  • JWT + Refresh Token Rotation: Access tokens expire in 15 min, refresh in 7 days
  • bcrypt Hashing: All passwords hashed with salt rounds = 10
  • RBAC (Role-Based Access Control): 6 roles with granular permissions
  • OTP Verification: SMS-based 2FA for sensitive operations
  • Session Tracking: Device fingerprinting to detect hijacks
API SECURITY
🔥 Backend Protection
  • Rate Limiting: 100 requests/minute per IP + per user
  • CORS Policy: Whitelist specific domains only
  • Helmet.js Headers: XSS, clickjacking, MIME-sniffing protection
  • SQL Injection Prevention: Parameterized queries, prepared statements
  • Input Validation: Sanitize all user inputs
MONITORING
🔍 Audit & Logging
  • Audit Logs: Track all sensitive operations (who, what, when)
  • Security Event Tracking: Failed logins, unauthorized access attempts
  • Centralized Logging: All logs sent to Sentry + ELK
  • Real-time Alerts: Suspicious patterns trigger immediate notifications
INFRASTRUCTURE
🏗️ System Security
  • Environment Variables: Never hardcode secrets (use .env)
  • TLS/SSL: All traffic encrypted in transit
  • API Keys Rotation: Regular rotation of external service credentials
  • Database Encryption: At-rest encryption enabled
⚠️ Critical Implementation Order: Start with JWT + bcrypt (foundation). Then add rate limiting & CORS. Finally, implement audit logging & monitoring.
⚡ Performance Optimization & DevOps Strategy
Making your system production-ready with speed, reliability, and observability
DATABASE PERFORMANCE
📦 Query & Schema Optimization
  • SQL Indexing: All FK, date, and frequently-queried columns indexed
  • Query Optimization: EXPLAIN PLAN analysis, avoid N+1 queries
  • Pagination: Limit result sets (20-50 items per page)
  • Connection Pooling: Max 20 connections, min 5 (dynamic scaling)
  • Optimized Joins: Use INNER JOIN where possible, minimize cartesian products
-- Example: Emergency search optimization SELECT h.id, h.name, h.lat, h.lng, bss.blood_group, bss.total_available FROM hospitals h INNER JOIN blood_stock_summary bss ON h.id = bss.hospital_id WHERE bss.blood_group = 'O+' AND ST_Distance_Sphere( POINT(h.lat, h.lng), POINT(?, ?) ) < 50000 -- 50km radius ORDER BY ST_Distance_Sphere(...) ASC LIMIT 3;

From basic forecasting to research-grade predictive intelligence
MODEL METRICS
📈 Accuracy & Validation
  • RMSE (Root Mean Square Error): Measure prediction variance
  • MAE (Mean Absolute Error): Average absolute deviation
  • MAPE (Mean Absolute Percentage Error): % accuracy metric
  • Residual Analysis: Check for patterns in prediction errors
  • Cross-Validation: 5-fold CV to prevent overfitting
# Model evaluation in Python from sklearn.metrics import mean_squared_error, mean_absolute_error rmse = np.sqrt(mean_squared_error(y_true, y_pred)) mae = mean_absolute_error(y_true, y_pred) mape = np.mean(np.abs((y_true - y_pred) / y_true)) * 100
