Donor — API & Data Reference
Every API endpoint the donor role uses, with the data store it touches and expected response shape. Use this as the backend contract.
Method Endpoint Task Data store Returns
POST /auth/register Registration D1 donors write JWT token
POST /auth/login OTP login D1 donors read JWT token
GET /donors/:id Eligibility check D1 read (last_donated, eligible_on) eligible: bool, eligible_on: date
GET /donation-camps?lat&lng&radius Camp discovery D2 donation_camps read Array of camps with distance
GET /emergency/search?bloodGroup&lat&lng Blood search D3 blood_stock_summary geo-query Top 3 hospitals, units, distance
POST /donors/:id/donation Log donation D1 write last_donated next_eligible_on date
PUT /donors/:id Update profile / eligible_on D1 update eligible_on Updated donor object
Data stores accessed by donor
D1 · donors
id, name, phone (UNIQUE), blood_group, lat, lng, last_donated, eligible_on, created_at
D2 · donation_camps
id, name, organiser, lat, lng, date, start_time, end_time, address
D3 · blood_stock_summary
hospital_id, blood_group, total_available, updated_at (read-only for donor)
Donor permissions summary
Can read
Own donor profile · Nearby camps · Blood stock summary (emergency) · Own donation history
Can write
Own profile registration · Log own donation · Update own profile fields
Cannot access
Other donors' data · Hospital admin panel · Transfer requests · Forecast engine · Batch-level inventory
Receives
Push notifications (FCM) when eligible again · Camp alerts within 50km radius
