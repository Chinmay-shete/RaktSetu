You are a Senior Full-Stack Engineer and DevOps Architect performing a complete Pre-Production 
Readiness Audit for a project called **RaktSetu** — an AI-powered blood logistics and donor 
coordination platform built for the Indian healthcare market.

The project stack is:
- **Frontend:** React + Vite (SPA)
- **Backend:** Node.js + Express (REST API)
- **AI Microservice:** Python + Flask
- **Database:** MySQL with spatial indexing (ST_Distance_Sphere)
- **Maps:** Leaflet.js + OpenStreetMap
- **Auth:** JWT-based, single unified login endpoint across 6 portals

Your job is to perform a deep, honest audit across EVERY dimension listed below and produce 
a structured **Production Readiness Report in Markdown format**.

---

## AUDIT SCOPE — CHECK EVERY SINGLE ITEM BELOW

---

### 1. 🔐 AUTHENTICATION & AUTHORIZATION AUDIT
- Is JWT implemented correctly? (secret strength, expiry, refresh logic)
- Is the single login endpoint safely routing all 6 portal roles?
- Are protected routes guarded on BOTH frontend AND backend?
- Is there any role-escalation vulnerability? (can a donor access hospital admin routes?)
- Are tokens stored safely? (localStorage vs httpOnly cookie risk)
- Is logout properly invalidating tokens?
- Rate limiting on the login endpoint?
- Brute-force protection?

### 2. 🗄️ DATABASE AUDIT (MySQL)
- Are all foreign keys and indexes defined correctly?
- Is ST_Distance_Sphere used with proper SRID handling?
- Spatial index on the location columns?
- Are there any N+1 query problems in Express routes?
- Connection pooling configured? (not raw createConnection per request)
- SQL injection protection everywhere? (parameterized queries / ORM)
- Are sensitive fields (passwords) hashed with bcrypt with salt rounds ≥ 10?
- Are transactions used for multi-table writes?
- Is there a DB connection error handler that won't crash the server?

### 3. 🌐 EXPRESS BACKEND AUDIT
- Is every API route returning consistent JSON response shapes?
- Are HTTP status codes correct? (200/201/400/401/403/404/500)
- Global error handler middleware present and catching unhandled errors?
- CORS configured correctly for production origin?
- Helmet.js or equivalent security headers in place?
- Are file uploads (if any) validated and size-limited?
- Environment variables used for ALL secrets (DB password, JWT secret, Flask URL)?
- Is the server crashing if Flask AI service is down? (should fail gracefully)
- Are all async route handlers wrapped in try/catch or express-async-errors?
- Input validation/sanitization on all POST/PUT body fields?
- Are all API endpoints returning 401 for unauthenticated access where required?

### 4. 🤖 FLASK AI MICROSERVICE AUDIT
- Is the Flask service running in production mode (not debug=True)?
- Is it behind a WSGI server (Gunicorn) instead of Flask's dev server?
- Are all AI endpoints responding within acceptable timeouts (< 5 seconds)?
- What happens when the AI model is slow or fails? Does Express handle the timeout gracefully?
- Is the Flask service URL configured via environment variable, not hardcoded in Express?
- Are there request validation checks on Flask's input?
- Is the AI microservice protected from direct public access? (only Express should call it)
- Memory usage — does the model stay loaded in RAM between requests or reload every time?

### 5. ⚛️ REACT FRONTEND AUDIT
- Is the production build (vite build) clean with no console.error or warnings?
- Are all 6 portal dashboards loading correctly?
- Are protected routes redirecting unauthenticated users to login?
- Are there any hardcoded API base URLs? (must use .env VITE_API_URL)
- Error boundaries in place for major sections?
- Is the Leaflet map loading without tile errors?
- Are past-date issues in forms fixed? (camp registration date validation)
- Mobile responsiveness on all major portal pages?
- Are duplicate Navbar/Footer components removed?
- Is the bundle size reasonable? (run: npx vite build and check dist size)
- Accessibility: label-control associations fixed?
- Loading states and skeleton screens for API calls?
- Are state/district dropdowns fully populated?

### 6. 📡 API INTEGRATION AUDIT
- Test every single API endpoint end-to-end:
  - Auth: Login (all 6 roles), token refresh, logout
  - Donor: Register, profile update, donation history
  - Hospital: Request blood, approve donor, manage staff
  - Admin: Dashboard stats, user management
  - Blood Bank: Inventory update, expiry alerts
  - Camp Organizer: Create camp, register donor, view registrations
- Are all form submissions reaching the backend correctly?
- Are success/error responses shown to the user with proper UI feedback?
- Is the blood request matching algorithm (AI-assisted) returning correct results?

### 7. 📊 PERFORMANCE AUDIT
- What is the average response time of the 5 most-used API endpoints?
- Is any endpoint doing synchronous blocking operations in Node.js?
- Are database queries indexed properly for the most frequent queries?
  - donor search by blood group + location
  - hospital blood requests by status
  - donation history by donor_id
- Is caching in place for static/semi-static data (blood groups, hospitals list)?
- Is the React bundle code-split / lazy-loaded by portal role?
- Are images optimized and properly sized?

### 8. 🚀 SCALABILITY & CAPACITY ESTIMATE
Based on the architecture, calculate and report:

**Single-instance capacity estimate:**
- Node.js/Express: How many concurrent requests can this handle?
  - Default: ~500–1000 concurrent with connection pool of 10
  - With cluster mode (all CPU cores): multiply by core count
- Flask AI: What is the bottleneck? (single-threaded Python GIL)
  - Single Gunicorn worker: ~5–20 concurrent AI requests
  - With 4 workers: ~20–80 concurrent AI requests
- MySQL: Connection pool size × query duration = throughput
- Leaflet/OSM: No load on our server (client-side + CDN)

**Realistic concurrent user estimate:**
- Light usage (browsing, viewing): ~500–1,000 simultaneous users
- Active usage (form submissions, AI queries): ~100–300 simultaneous users
- Heavy AI requests simultaneously: ~20–80 (Flask bottleneck)

**Scaling path:**
- Horizontal scaling: Can Express be run with PM2 cluster mode?
- Load balancer ready? (Nginx)
- Can Flask workers be increased?
- Is MySQL connection pool configured for multi-instance?
- CDN for static React build?
